# Issue #71: dashboard redesign review

Implementation branch: `feat/71-dashboard-redesign`, based on `main` at `9de23a9`.
The [approved plan](ISSUE-71-PLAN.md) records the scope and commit sequence.

## Changes to review

- Compact header in document flow, with staff identity/role, sign-out, and the
  existing weather control. Navigation wraps on mobile, includes labeled icons,
  and exposes the current section with `aria-current="page"`.
- Shared HackUTA color/size tokens, quieter surfaces, consistent page headings,
  buttons, fields, table spacing, and text-based status badges.
- Application table/mobile cards and review panels retain their existing controls,
  filters, pagination, query parameters, and focus behavior. Resume preview retains
  its native dialog and document-viewer dimensions.
- Decision emails share table/status patterns, have a keyboard-scrollable mobile
  table and contextual loading skeletons, and recover query failures locally through
  Try again. Application decisions remain distinct from email delivery states.
- Volunteer responsibilities, event cards, and protected workflow entry pages use
  the same headers, action links, status styling, and empty/loading states.
- Reduced-motion handling covers dashboard animation. New browser checks cover
  long content, keyboard interactions, zoom/reflow, and status/action text contrast.

The routes, authorization policy, participant data, review mutation contracts, and
email release logic are preserved. There are no new dependencies, package/lockfile
changes, backend function changes, migrations, or deployments. Email browser tests
use the isolated mock store; no live emails were released.

## Remaining issue scope

Participants and Volunteers are still protected “Coming soon” entry pages. Their
management tables/forms, camera scanning, event-management tables, and a general
audit-log table belong to separate workflows that are not mounted in this SPA.
Assigned events remain cards and application history remains a timeline. Shared
visual patterns are available for future workflows, but their table/form acceptance
criteria must remain open until those workflows exist.
